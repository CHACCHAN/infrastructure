# エージェントへのジョブの委譲

リポジトリを扱うエージェントの役割分担。実行手順は [.agents/README.md](../../.agents/README.md#delegated-jobs)、安全規則と検証は [AGENTS.md](../../AGENTS.md)。

## 決定済み

- メインエージェントとして使う製品・モデルは、このプロジェクトでは指定しない。ここで決めるのは、メインがジョブを委譲するときの実行先と責任の境界だけ。
- 実装・調査・探索・草案・セカンドオピニオン・レビューの委譲には、Mistral Vibe CLI を使う。ジョブのモデルは CLI 側の設定に従い、リポジトリでは固定しない。
- 独立したジョブは並列に進める。実装ジョブには、リポジトリの外の使い捨てコピーを個別に渡す。委譲先は、さらに委譲しない。
- メインは判断、差分の確認、統合、検証、本番インフラの操作を担当する。すべての差分を読んでから取り込み、検証コマンドは自分で実行する。
- 設計文書・新規ロール・複数ファイルに及ぶ変更などは、実装とは別の Mistral Vibe CLI セッションで独立レビューを受ける。レビューは読み取り専用にする。
- 委譲先には秘密情報を渡さず、検証コマンドと実インフラへのアクセスを許さない。Vibe CLI の有効ツールを必要最小限に絞り、シェル・プロセスの実行、コネクタ、再委譲は有効にしない。ツールの制限は OS のサンドボックスではないため、本番の認証情報を渡してよい理由にはならない。
- 本番への変更には、その会話でのオーナーの明示的な実行依頼が必要。ジョブの委譲やレビューの依頼は、本番変更の許可ではない。
- 使わないエージェントの設定・実行ユーティリティ・手順は削除する。予備の実行経路や互換ラッパーは残さない。
